# Автоматизированное расширение признакового пространства рекомендательной системы с помощью графовых нейронных сетей и автоматического конструирования признаков

## Аннотация

В работе рассматривается автоматизированное расширение признакового пространства рекомендательной системы на данных KION с использованием графовых представлений пользователей и объектов и методов автоматического конструирования признаков (AutoFE). В качестве исходной точки зафиксированы временной протокол оценки и двухэтапный бейзлайн с CatBoost, достигающий на тестовом окне NDCG@10 = 0.1749 и лишь незначительно превосходящий популярность за последние семь дней (0.1738). Последовательное сравнение четырёх конфигураций (бейзлайн, +GNN, +AutoFE, +GNN+AutoFE) при неизменном протоколе показывает: AutoFE даёт статистически значимый прирост NDCG@10 +0.0049 (+2.8% отн.) с ростом MAP@10, MRR@10, покрытия каталога и устойчивости ансамбля; графовые признаки в текущей реализации ценности не несут (смена знака прироста между валидацией и тестом, ни один GNN-признак не входит в топ-20 по важности). Итоговая конфигурация — AutoFE. Новые признаки строятся без утечки будущих данных (принцип *as-of*); эффективность оценивается на независимом тестовом окне.

**Ключевые слова:** рекомендательные системы, KION, графовые нейронные сети, GNN, автоматическое конструирование признаков, AutoFE, ранжирование.

## 1. Введение

Качество рекомендательной системы зависит не только от алгоритма ранжирования, но и от того, насколько информативно представлены пользователи, объекты и их взаимодействия. При коротких историях просмотров коллаборативные модели получают ограниченные сведения о предпочтениях многих пользователей, а высокая концентрация взаимодействий на популярных объектах создаёт сильный неперсонализированный бейзлайн. В таких условиях дополнительная ценность признаков должна подтверждаться строгим сравнением на данных, не использованных при их построении.

Графовые нейронные сети (GNN) могут кодировать структуру связей между пользователями и объектами, а автоматическое конструирование признаков (AutoFE) позволяет систематически порождать и оценивать новые признаки и их преобразования. Предмет исследования — добавочная ценность этих сигналов для двухэтапного ранжирования при неизменных генерации кандидатов, целевой постановке и протоколе оценки.

**Цель работы** — экспериментально проверить, обеспечивает ли совместное применение GNN и AutoFE воспроизводимое улучшение качества относительно зафиксированного бейзлайна. Основное внимание уделяется NDCG@10; дополнительно рассматриваются другие метрики ранжирования, охват каталога, устойчивость результата и вычислительные затраты.

## 2. Данные

### 2.1. Набор данных

Эксперименты проводятся на открытом наборе **KION** — обезличенной истории просмотров российского сервиса онлайн-видео. Используется фиксированная версия репозитория данных (`data_en`, commit `f69775be`), обеспечивающая воспроизводимость. Набор содержит **5.48 млн взаимодействий** **962 тыс. пользователей** с **15.7 тыс. объектов** за период с 13 марта по 22 августа 2021 года. Каждая запись содержит идентификаторы пользователя и объекта, дату последнего просмотра, суммарную длительность просмотра и долю просмотренного контента; пары «пользователь — объект» уникальны. Дополнительно доступны демографические характеристики пользователей (пол, возраст, доход, наличие детей) и метаданные объектов (жанры, страны, год выпуска, возрастной рейтинг, тип контента).

### 2.2. Особенности данных

- **Короткие пользовательские истории**: медианная длина истории — 2 объекта, средняя — около 5.7. Коллаборативные модели располагают ограниченной информацией о предпочтениях значительной части пользователей.
- **Высокая концентрация на популярных объектах**: на 1% наиболее популярных объектов приходится около 45.7% взаимодействий, на топ-10 объектов — 18.7%. Это создаёт сильный неперсонализированный бейзлайн популярности и усложняет прирост за счёт персонализации.

Эти особенности задают контекст исследования: необходимо проверить, могут ли графовые представления и автосконструированные признаки повысить качество ранжирования при коротких историях и сильном бейзлайне популярности.

## 3. Протокол оценки и опорный бейзлайн

### 3.1. Временное разбиение и предотвращение утечек

Оценка выполняется по временному протоколу, имитирующему применение системы для прогнозирования будущих взаимодействий:

| Период | Окно | Объём взаимодействий |
|---|---|---|
| Train | до 8 августа 2021 | ≈ 4.65 млн |
| Valid | следующая неделя | ≈ 403 тыс. |
| Test | последние 7 дней (до 22 августа 2021) | ≈ 424 тыс. |

Случайное разбиение не применяется. Все статистики пользователей и объектов, популярность в скользящих окнах и коллаборативные представления вычисляются исключительно по истории, доступной до соответствующего целевого периода (принцип ***as-of***). При финальном тестировании модели и признаки пересчитываются по объединённой истории обучения и валидации; тестовое окно не используется для выбора конфигурации.

### 3.2. Формирование рекомендаций и метрики

Задача формулируется как ранжирование объектов каталога для каждого пользователя; релевантность бинарная. Оценка проводится в режиме **warm-start**: каталог включает объекты, имевшие хотя бы одно взаимодействие в предшествующей истории; уже просмотренное исключается из рекомендаций; пользователи без истории получают неперсонализированные рекомендации по популярности. Метрики вычисляются для каждого пользователя с непустым целевым множеством **на полном доступном тёплом каталоге**, а не на сэмплированных негативах: **Precision@10, Recall@10, MAP@10, NDCG@10, MRR@10, Coverage@10** (доля каталога в рекомендациях). Основная метрика — **NDCG@10**. Оцениваются 155 757 пользователей на валидации и 164 779 на тесте.

### 3.3. Сравниваемые модели

1. **Случайные рекомендации** — нижняя точка сравнения.
2. **Глобальная популярность** — по общему числу взаимодействий в доступной истории.
3. **Популярность за 7 дней** — ранжирование по числу взаимодействий в последнем недельном окне.
4. **iALS(+pop)** — implicit ALS (32 фактора, 15 итераций, регуляризация 0.1) на бинарной матрице взаимодействий; для пользователей без представления — резерв по популярности.
5. **Двухэтапная модель с CatBoost** — пул кандидатов из топ-100 объектов по iALS + топ-20 по популярности (холодным пользователям — популярное), затем переранжирование CatBoost Ranker (YetiRank) по **46 признакам**: статистики пользователей и объектов, популярность в окнах 1/7/30 дней, гендерные агрегаты, оценка iALS, демография и метаданные контента.

### 3.4. Обучение ранкера и воспроизводимость

Обучающие группы CatBoost формируются на отложенном временном срезе внутри обучающей выборки: история признаков заканчивается до целевой недели, позитивы определяются по взаимодействиям в эту неделю, для каждого пользователя добавляются 20 случайных негативов из тёплого каталога. Ранняя остановка — по отдельной валидационной неделе; после выбора числа итераций ранкер переобучается на обучении+валидации для финального тестирования. Ранкер — ансамбль из двух моделей CatBoost с разными seed, обучаемых параллельно на **2× NVIDIA T4**, с усреднением оценок при инференсе. Гиперпараметры зафиксированы: глубина 8, learning rate 0.05, L2-регуляризация 5; широкого поиска не проводится.

## 4. Результаты опорного бейзлайна

| Модель | P@10 | R@10 | MAP@10 | NDCG@10 | MRR@10 | Cov.@10 |
|---|---:|---:|---:|---:|---:|---:|
| Случайные рекомендации | 0.0002 | 0.0007 | 0.0002 | 0.0004 | 0.0004 | 1.0000 |
| Популярность (вся история) | 0.0403 | 0.2266 | 0.1160 | 0.1578 | 0.1717 | 0.0024 |
| Популярность (7 дней) | 0.0483 | 0.2711 | 0.1218 | 0.1738 | 0.1802 | 0.0022 |
| iALS(+pop) | 0.0286 | 0.1555 | 0.0781 | 0.1072 | 0.1162 | 0.0185 |
| iALS + популярность → CatBoost | 0.0481 | 0.2685 | 0.1239 | **0.1749** | 0.1829 | 0.0049 |

Основные наблюдения:

- **Популярность за 7 дней — сильный неперсонализированный бейзлайн**: NDCG@10 = 0.1738 против 0.1578 у популярности за всю историю (+10.1% отн.) — временная актуальность взаимодействий критична.
- **Двухэтапная модель достигает NDCG@10 = 0.1749**, превосходя недельную популярность лишь на ~0.65% относительных; MAP@10 и MRR@10 выше, а P@10 и R@10 — немного ниже. Преимущество ранкера зависит от метрики и не является универсальным улучшением.
- **Coverage@10 ранкера ≈ 0.49%** против 0.22% у недельной популярности — рекомендации распределены по более широкому набору объектов при низком абсолютном охвате.
- **iALS(+pop) уступает популярности** (NDCG@10 = 0.1072), что согласуется с короткими историями; при этом оценка iALS — самый важный отдельный признак ранкера: слабая автономная модель не исключает ценности её оценки при совместном ранжировании.
- **Valid и test расходятся в ранжировании моделей** (на валидации недельная популярность 0.1848 выше двухэтапной 0.1843) — наблюдаемый прирост невелик и требует проверки устойчивости.
- **Важность признаков сконцентрирована**: на оценке iALS и четырёх показателях популярности в коротких окнах — около 82.5% суммарной важности; контентные метаданные, демография и статистики историй занимают нижние позиции (что характеризует конкретный ранкер, а не бесполезность этих признаков).

## 5. Подход к автоматизации порождения признаков

### 5.1. Мотивация и исследовательский вопрос

Двухэтапная модель с 46 вручную спроектированными признаками лишь незначительно превосходит недельную популярность, а важность сконцентрирована на горстке признаков. Это не означает, что ручное проектирование исчерпано, но показывает, что простое объединение привычных статистик не гарантирует прироста. **Исследовательский вопрос: можно ли систематически находить дополнительные сигналы и полезные комбинации признаков, не включённые в исходный набор?**

### 5.2. Метод

**AutoFE: пространство спеков + компилятор.** Признак описывается декларативной спекой `(связь user→категория) × (временное окно / затухание) × (условие) × (агрегат)` — например, «активность объектов того же жанра за 14 дней». Компилятор вычисляет значение любой спеки по принципу as-of (только по истории до cutoff) для произвольных пар (user, item). Прямые связи user–item из пространства исключены: в KION пары глобально уникальны, а просмотренное фильтруется из рекомендаций — такие признаки тождественно равны нулю. Полное пространство — ~420 спеков.

**GNN-компилятор.** Гетерогенный граф (пользователи, объекты, значения категорий), 2-слойная R-GCN на чистом PyTorch, обучение — link prediction на истории до cutoff (зеркально iALS). Для пары (user, item) строятся производные: скалярное произведение, косинусная близость, L2-расстояние, нормы векторов, близость пользователя к категориям кандидата.

**Двухступенчатый отбор.** IG-скрининг кандидатов на OOF-парах (48 выживших) → дедупликация (избыточность внутри кандидатов и клоны ручных 46 признаков) → wrapper: прирост ΔNDCG@10 **настоящего ранкера на реальных кандидатах** (iALS ∪ Pop), блоками по 6 спеков и жадный отбор при фиксированном бюджете в 50 фитов; потолок размера итогового набора — 12 спеков, порог принятия спеки — ΔNDCG ≥ 0.00005.

**Два уровня данных.** Фаза поиска идёт на подвыборке 200 тыс. пользователей (≈23.5% объёма train) для быстрой итерации; значения отобранных спеков затем пересчитываются на полных данных на каждом cutoff. Отбор — только на valid; тестовое окно — один заход в конце.

### 5.3. План экспериментов

При неизменных пуле кандидатов, целевой постановке, ранкере и протоколе последовательно сравниваются:

1. исходная модель с зафиксированными признаками (`A0_manual`);
2. исходная модель + графовые признаки (`A_GNN`);
3. исходная модель + автоматически сгенерированные признаки (`A_AutoFE`);
4. совместное использование GNN и AutoFE (`A_All`).

### 5.4. Гипотеза и контроль утечек

**Гипотеза:** автоматизированное расширение признакового пространства с использованием GNN и AutoFE способно обеспечить воспроизводимый прирост качества относительно бейзлайна. Исследуются не только NDCG@10, но и вклад отдельных групп признаков, устойчивость и вычислительная стоимость; отсутствие прироста также рассматривается как значимый результат.

Все новые признаки удовлетворяют принципу *as-of*: при вычислении используется только информация, доступная до целевого периода — включая построение графа, обучение GNN, вычисление эмбеддингов, генерацию и отбор признаков. Финальное сравнение — на независимом тестовом окне, не используемом для выбора признаков или настройки метода.

## 6. Эксперименты и результаты

### 6.1. Схема сравнения

В каждом arm изменяется только признаковое пространство ранкера:

| Arm | Признаковое пространство |
|---|---|
| `A0_manual` | 46 исходных признаков — контрольное воспроизведение бейзлайна |
| `A_GNN` | 46 исходных + графовые эмбеддинги пользователей и объектов |
| `A_AutoFE` | 46 исходных + автоматически сгенерированные признаки |
| `A_All` | 46 исходных + графовые + автосгенерированные |

Всё остальное зафиксировано: пул кандидатов (топ-100 iALS + топ-20 популярности), CatBoost YetiRank (глубина 8, lr 0.05, L2 = 5), временные окна, метрики. Каждый arm обучается с **двумя seed** (4 arm × 2 seed = 8 ранкеров); метрики вычисляются для ансамбля с усреднением оценок, а разброс NDCG@10 между seed (σ) служит мерой устойчивости. Перед сравнением выполняется контроль воспроизведения: метрики `A0_manual` на тесте должны совпасть с эталонным ноутбуком бейзлайна (NDCG@10 = 0.17494, MAP@10 = 0.12387, R@10 = 0.26846) с допуском 0.01.

### 6.2. Воспроизведение бейзлайна

`A0_manual` на тесте: NDCG@10 = 0.17487 (Δ = −0.00007), MAP@10 = 0.12382 (Δ = −0.00005), R@10 = 0.26843 (Δ = −0.00003). Расхождения на три порядка меньше допуска — протокол воспроизведён корректно, сравнение arm валидно.

### 6.3. Результаты на тестовом окне

| Arm         |   P@10 |   R@10 | MAP@10 |     NDCG@10 | MRR@10 | Cov.@10 |  σ NDCG |       Δ NDCG |
| ----------- | -----: | -----: | -----: | ----------: | -----: | ------: | ------: | -----------: |
| `A0_manual` | 0.0481 | 0.2684 | 0.1238 |     0.17487 | 0.1827 |  0.49 % | 0.00032 |            — |
| `A_GNN`     | 0.0481 | 0.2685 | 0.1232 |     0.17433 | 0.1818 |  0.51 % | 0.00031 |     −0.00054 |
| `A_AutoFE`  | 0.0483 | 0.2691 | 0.1294 | **0.17973** | 0.1914 |  0.58 % | 0.00012 | **+0.00486** |
| `A_All`     | 0.0483 | 0.2691 | 0.1294 |     0.17973 | 0.1914 |  0.60 % | 0.00004 |     +0.00486 |

**Автогенерация признаков даёт статистически значимый прирост.** `A_AutoFE` — единственная конфигурация с эффектом, многократно превышающим межсидовый шум: NDCG@10 **+0.0049 (+2.8 % отн.)**, MAP@10 **+4.5 %**, MRR@10 **+4.8 %**. Coverage@10 вырос с 0.49 % до 0.58 % (+18 % отн.) — рекомендации охватывают более широкую часть каталога. Стабильность повысилась в 2.7 раза (σ: 0.00032 → 0.00012). Прирост не «сгорел» при переносе с валидации на тест, а усилился (+0.0019 → +0.0049): сгенерированные признаки отражают устойчивые закономерности, а не подгонку под валидационное окно. Преимущество двухэтапной модели над недельной популярностью выросло с +0.65 % до **+3.4 %** относительных.

**Графовые признаки в текущей реализации ценности не несут.** У `A_GNN` на валидации +0.0005 NDCG, на тесте **−0.0005** — смена знака при переносе указывает на отсутствие обобщающей способности: эмбеддинги фиксируют специфику валидационного периода, а не устойчивые предпочтения.

**Совместное применение не добавляет ничего поверх AutoFE.** `A_All` совпадает с `A_AutoFE` с точностью до шума (0.179730 против 0.179734, Δ = −0.000004 при σ ≈ 0.0001). Вся ценность `A_All` обеспечена автогенерацией; GNN-ветка лишь увеличивает вычислительные затраты и усложняет пайплайн.

- **Что нашёл AutoFE.** В топ-20 вошли три автоматических признака: `ufe_genre_d14_all_count` (10-е место), `ufe_country_d14_all_count`, `ufe_age_d7_all_log1p_count`. Это контекстно-условные агрегаты популярности: активность объектов того же жанра и той же страны производства за 14 дней и логарифм активности возрастной группы за 7 дней. Ручной набор содержал только безусловную популярность и простые гендерные агрегаты — автоматический поиск заполнил именно эту нишу, скомбинировав контентные/демографические срезы с короткими временными окнами.
- **Автоматические признаки обходят большинство ручных контентно-демографических** (`item_gender_share`, `item_rate_within_gender`, `i_genres`), хотя каждый в отдельности имеет скромную важность. Это не противоречит приросту +0.0049 NDCG: важность CatBoost не учитывает взаимодействия признаков, а ценность условных агрегатов — в уточнении порядка верха списка, что согласуется с ростом MAP@10 и MRR@10 при почти неизменных P@10/R@10.
- **Ни один GNN-признак не вошёл в топ-20** — ещё одно независимое подтверждение вывода о неработоспособности графовой ветки в текущей реализации.

### 6.5. Выводы

1. Гипотеза работы подтверждена **частично**: автоматизированное расширение признакового пространства улучшает качество ранжирования, однако весь эффект обеспечен AutoFE.
2. Финальная конфигурация — **`A_AutoFE`**: NDCG@10 = 0.17973 (+2.8 % к ручному бейзлайну, +3.4 % к недельной популярности) при лучшей устойчивости (σ = 0.00012) и покрытии каталога. Механизм прироста — автоматически найденные контекстно-условные агрегаты популярности (жанр/страна/возраст × короткие окна).
3. **GNN-признаки в текущем виде нецелесообразны.** Чтобы они начали приносить пользу, требуется переработка их порождения: проверка на утечку при обучении графа, размерность и схема агрегации эмбеддингов, регуляризация.

## 7. Заключение

Зафиксирован временной протокол оценки и двухэтапный бейзлайн на CatBoost (NDCG@10 = 0.1749 на тестовом окне), корректно воспроизведённый в ходе экспериментов (расхождение < 0.0001). В контролируемых условиях — при неизменных генерации кандидатов, целевой постановке, конфигурации ранкера и протоколе — установлена добавочная ценность двух способов расширения признакового пространства. Автоматическое конструирование признаков дало воспроизводимый прирост NDCG@10 +0.0049 (+2.8 % отн.) с одновременным ростом MAP@10, MRR@10, покрытия каталога и устойчивости; анализ важности показал, что источником эффекта стали контекстно-условные агрегаты популярности (по жанру, стране и возрастной группе в коротких окнах), отсутствовавшие в ручном наборе. Графовые признаки не обобщаются на тестовое окно (смена знака прироста между валидацией и тестом, отсутствие в топ-20 по важности), а их совместное применение с AutoFE повторяет результат чистого AutoFE (Δ = −0.000004). Итоговая конфигурация — `A_AutoFE`; включение GNN-ветки в финальную модель нецелесообразно без переработки способа порождения графовых представлений.

## 8. Воспроизведение эксперимента

### 8.1. Требования к окружению

- **Аппаратура**: GPU-инстанс (эксперимент выполнен на Kaggle **2× NVIDIA T4**, ~29 ГБ RAM). CatBoost обучает одну модель на одном устройстве, поэтому обе карты заняты seed-ансамблем; при одном GPU модели обучаются последовательно, при отсутствии GPU — на CPU (медленно).
- **ПО**: Python 3.10+, Jupyter. Ноутбук сам устанавливает недостающие пакеты (`%pip install -q implicit catboost tqdm`); на Kaggle torch / numpy / pandas / scipy / matplotlib / seaborn предустановлены. Для локального запуска полный список:

```txt
# requirements.txt
catboost>=1.2
implicit>=0.7
numpy
pandas
scipy
matplotlib
seaborn
tqdm
torch            # GNN-ветка (A_GNN, A_All)
```

### 8.2. Данные

Датасет KION **скачивается автоматически** при первом запуске ноутбука из фиксированного коммита репозитория (`data_en`, commit `f69775be`) в `./data/data_en/` — вручную ничего скачивать не нужно (в Kaggle включите Internet). Файлы: `interactions.csv`, `users_en.csv`, `items_en.csv`. Каталог данных в `.gitignore` не версируется.

### 8.4. Запуск

1. Загрузить `kion_exp.ipynb` в ноутбук с GPU (Kaggle: *Create Notebook* → Settings → Accelerator = **GPU T4 x2**, Internet = **On*).
2. **Run All**. Полный прогон — ~2.5–4 часа. Стадии пайплайна:
   - загрузка (автоматически) и очистка данных, временной сплит c assert-контролем непересечения окон;
   - фаза поиска признаков на подвыборке 200 тыс. пользователей: компиляция ~420 спеков → IG-скрининг (48 выживших) → дедупликация → wrapper с бюджетом 50 фитов (потолок 12 спеков);
   - финальные руки на полных данных: 4 arm × 2 seed ранкеров CatBoost YetiRank;
   - оценка на valid, переобучение на train+valid, однократная оценка на test;
   - итоговая таблица, важности признаков и SANITY-проверка.
3. Для быстрой проверки пайплайна — `CFG.fast_run = True` в ячейке конфигурации: подвыборка 5 тыс. пользователей, урезанные бюджеты, ~10–15 минут. **Метрики FAST-режима не характеризуют исследование.**
4. `kion_baseline.ipynb` самодостаточен и служит источником зафиксированного протокола и эталонных метрик для SANITY-проверки (артефакты — в `./artifacts/`).

### 8.5. Чекпоинты и возобновление после сбоя

Все стадии пишут чекпоинты на диск: завершённый поиск (`search_artifacts.json`), собранные фреймы и руки (`autofe_artifacts/ckpt/`), каждый фит ранкера чекпоинтится, большие фреймы собираются чанками по 3 млн строк. После смерти ядра достаточно снова **Run All** — выполненные стадии переиспользуются с диска, обучение продолжится с последней завершённой точки, а не с нуля. Принудительный пересчёт поиска — `CFG.force_search_rerun = True` (или удалить `search_artifacts.json`).

В окружениях с ограниченным временем сессии (Kaggle) перезапускайте ноутбук там, где сохранился рабочий каталог (`/kaggle/working`): новый kernel с пустой рабочей директорией означает потерю чекпоинтов и полный пересчёт.

### 8.6. SANITY-проверка

В конце пайплайна метрики `A0_manual` на тесте автоматически сравниваются с эталонными значениями ноутбука бейзлайна:

```txt
KAGGLE_TEST = {"NDCG@10": 0.17494, "MAP@10": 0.12387, "R@10": 0.26846}   # допуск 0.01
```

Если расхождение по любой метрике превышает 0.01, пайплайн сообщает «РАСХОЖДЕНИЕ > 0.01 — проверьте протокол!» — это признак нарушения протокола (утечка, неверное разбиение, изменение пула кандидатов). В нашем прогоне расхождения составили менее 0.0001 по всем метрикам.

### 8.7. Ожидаемые результаты

Таблица раздела 6.3 воспроизводится с точностью до межсидового шума (σ ≈ 0.0001–0.0005 по NDCG@10): CatBoost на GPU не гарантирует побитовой детерминированности, поэтому расхождения в третьем знаке после запятой являются нормой. Ключевые воспроизводимые факты: SANITY проходит (Δ < 0.0001), `A_AutoFE` даёт прирост NDCG@10 ≈ +0.005, `A_GNN` — около нуля или отрицательный, `A_All` совпадает с `A_AutoFE`, а в топ-20 по важности входят контекстно-условные агрегаты популярности (`ufe_genre_d14_all_count`, `ufe_country_d14_all_count`, `ufe_age_d7_all_log1p_count`).
